# Account preferences, recovery and reminders

- GET/PUT `/api/v1/users/me/settings`: authenticated owner only. Fields: emailReminders, inAppNotifications, enrollmentAlerts, profileVisible (booleans), cancellationNoticeHours (Tutor only: 0,6,12,24,48), version. PUT uses optimistic version; stale updates 409. Defaults true/true/true/true/12, version 0 before first save. Unsupported 2FA/automatic acceptance controls are not presented as saved preferences.
- POST `/api/v1/auth/forgot-password` {email}: generic 202 for unknown/disabled accounts and throttled resends (60 seconds per account). Email has fixed configured frontend origin; no caller-supplied redirect. Delivery failure 503; no valid reset token committed on failure.
- POST `/api/v1/auth/reset-password` {token,password}: 12–128 characters; SHA256 token hash stored, 30-minute expiry, one-time use, latest successful request supersedes prior tokens. Invalid/expired/replayed tokens 400. Password update, token consumption and revocation of all refresh sessions commit atomically. Existing access JWT expires naturally within 15 minutes.
- Booking response includes cancellationNoticeHours and cancellationDeadlineUtc; Redis holds and confirmed bookings snapshot the Tutor policy. Student cancellation after deadline is 409; Tutor may cancel until lesson starts. Repeated cancellation remains idempotent. No money/late fee is implied.
- Service-only directory endpoints require short-lived JWT role Service + scope identity.directory, never exposed by Gateway. Returns actual account email/preferences to reminder workers; Tutor search excludes accounts whose profileVisible is false.
- Reminder: booking and course sessions, actual account recipient, opt-out applied at send time, UTC source times formatted as Vietnam time in email. No expired session reminder. SMTP local sink is Mailpit; production SMTP needs configuration. Delivery is at-least-once under crash ambiguity, bounded retries, no exactly-once claim.
